## 論文はなにを報告しているか

ARC-AGI は「人間には簡単、AI には難しい」ことを設計原理とする流動性知能
(初見のタスクへの適応力)のベンチマーク。各タスクは数個のデモペア
(入力グリッド→出力グリッド)から規則を発見し、テスト入力に適用する形式で、
事前に対策できないことが特徴。2025年のコンペは難化版 **ARC-AGI-2** が対象。

### 2025年の結果(2章)

- Kaggle: 1,455チーム・15,154件の応募。**1位 NVARC が private セットで 24.03%**
  (1タスクあたり計算コスト $0.20)。2位 the ARChitects 16.53%、3位 MindsAI 12.64%。
- 論文トラックは 90本(前年 47本)に倍増。
  1位 **TRM**、2位 **SOAR**(自分の探索ログでLLMを自己改善)、3位 **CompressARC**。
- Anthropic / Google DeepMind / OpenAI / xAI の4社がモデルカードで
  ARC-AGI スコアを公表し、業界標準ベンチマークになった。

### 中心テーマ: refinement loop(3章)

2025年の最重要トレンドは **「フィードバック信号に導かれて、プログラムや
モデルを1周ごとに少しずつ良くするループ」** の台頭。同じ構造が複数の形で現れた:

1. **進化的プログラム合成**(Berman: 自然言語プログラム / Pang: Pythonプログラム)
   — 探索フェーズで候補を大量生成 → 検証フェーズでデモペア採点 →
   全デモペア正解まで反復。→ `refinement_loop_demo.py` がこの骨格。
2. **テスト時学習(TTT)** — 事前学習済みモデルの「重み」を推論時に
   そのタスクの例で微調整する。重み空間での refinement loop。
   2024年(ARChitects)・2025年(NVARC)の優勝はどちらもこれ。
3. **事前学習ゼロの深層学習** — TRM(7Mパラメータで ARC-AGI-1 45%)や
   CompressARC(76Kパラメータ・事前学習なし・データセットなし・勾配降下のみで
   ARC-AGI-1 20%)。ランダム初期化した極小ネットに「そのタスクを解くプログラム」を
   テスト時にフィットさせる。→ `trm_mini.py` 参照。
4. **商用モデルの Chain-of-Thought / ハーネス** — 推論トークン列も
   「自然言語プログラムの反復改良」と見なせる。アプリ層のハーネス(Poetiq)は
   Gemini 3 Pro を 31%($0.81/task)→ 54%($31/task)へ引き上げた
   (Claude Opus 4.5 でも同等の精度向上、コストは約2倍)。

### 知識依存の過学習(4章)— もう1つの重要な主張

現在の AI の推論性能は **事前学習コーパスの知識カバレッジに根本的に拘束**
されており、人間の推論(知識に縛られない)とは質が異なる。
著者らは、検証ハーネスが ARC に一切言及していないのに Gemini 3 が
ARC の色マッピング(3=緑 等)を正しく使って推論した証拠を挙げ、
**「記憶では解けない設計のベンチマークでも、公開データと私的テストの分布が
近ければ『新種の過学習』が起きる」** と警告している。
これが、静的推論から対話的推論(探索・計画・記憶・目標獲得・アラインメント)へ
形式を一新する **ARC-AGI-3**(2026年初頭リリース予定)につながる。

### 結論の要点

- 「知識カバレッジが十分 + 検証可能なフィードバック信号がある」領域は
  すでに確実に自動化可能(新しい科学は不要)。
- 一方、Grand Prize(効率よく解く)には依然として新しいアイデア
  (知識と推論の分離など)が必要。
- AGI 判定の基準は Chollet の言葉に集約される:
  「普通の人間には簡単で AI には難しいタスクを作ることが不可能になったとき、
  AGI が来たと分かる」。その意味で AGI は未達。

## デモコードと論文の対応

```
refinement_loop_demo.py
  探索フェーズ  = mutate() で候補プログラムを生成(論文では LLM が担う)
  検証フェーズ  = fitness() がデモペア採点でフィードバック信号を生成
  refinement_loop() = 全デモペア正解までこのサイクルをタスクごとに反復
  → 実行すると、数世代で「180度回転」「色交換+左右反転」の規則を発見し、
    テスト入力に適用する様子が見える。

trm_mini.py
  improvement_step() = 潜在 z を n 回更新(考える)→ 答え y を書き直す
  forward()          = これを最大 N_sup=16 回繰り返し答えを段階的に改良
  deep supervision   = 途中の答案にも毎回損失を取る学習法
```

どちらも「**生成 → 検証 → フィードバックで改良**」という同一の構造を、
片方は記号(プログラム)空間で、もう片方は重み・潜在空間で回している——
これが本レポートの一番伝えたいことである。
