このリポジトリの全設計がこの一文から出ている。検査は「落ちる」ことより 「走らなかったことを隠さない」ことが難しい —— パーサが無い / 比較対象が両方とも空 / 手前のガードで早期 return / そのマシンにしか無いファイルに依存。どれも緑に見える。

1改善ループ

失敗を、二度と起きない形に変換する手順
1
失敗を「挙動」として書く

「スクリプトが間違っていた」ではなく「node が無いとき exit 0 だった」。挙動なら assert できる。

2
置き場所を選ぶ

毎回必ず起きるなら hook。環境で差が出るなら doctor。base と比べて初めて見えるなら CI。

3
空虚に通らない検査を書く

ガードに実際に到達する入力で。比較の前に「在る」ことを先に assert する。

4
故意に壊して、落ちるのを見る

使い捨てコピーで。破壊が適用されたことを先に確認する。通るところしか見ていない検査は証拠ではない。

5
台帳に記録する

docs/LEDGER.md に失敗・検査・壊して確認した旨。検査が実在するかを ledger.sh が検証する。

6
検査が覆った散文を消す

CLAUDE.md は毎セッション全文ロードされる。飛ばされがちな唯一の手順で、飛ばすと固定費だけが積む。

4繰り返した失敗の「形」

28 行の台帳のうち、過半数がこの 4 型に収まる
A. 変形後の値を、変形前の綴りで探す

ID は 8 文字に切られ、数値は丸められ、vitest は CI でだけ色を付ける。 5 回発生。最後の 1 回は変形していたのが自分のコードではなく外部ツールだった。

→ 剥がす・導出する。二度書かない
B. 全滅が合格に見える

存在しないファイルの cksum 同士は一致する。壊れたフックは何も書かないので「変化なし」。 ハーネスが壊れていたため md5 が 3 つとも空文字列で「churn なし」と判定した。

→ 否定の前に肯定を assert する（在る・空でない・行がある）
C. そのマシンでしか走らない

python3 がある環境／ない環境。$HOME/.claude がある環境／ない環境。 CI で 3 検査が無言のまま未実行だったが、どれも台帳に「検証済み」と書かれていた。

→ プローブを合成する。same-everywhere.sh で検査数の一致を検証
D. 一方を直すと、もう一方が黙って壊れる

ログを staging に移したら doctor の検査が「変化しない 2 つ」を比べ始めた。 2 つある書き手の 1 つだけ直すと、もう 1 つが発火するまで直ったように見える。

→ eval が元の失敗を再生する。読んで考えるだけでは気づけない
