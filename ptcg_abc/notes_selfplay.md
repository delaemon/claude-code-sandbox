# 自己対戦による重み学習の結果 (train_selfplay.py)

`agent.py` の意思決定スコア 16 個を重みベクトル化し、(1+1)-ES で最適化した。
3 回の実験の顛末は、ノイズの多い対戦型適応度の教科書的なケーススタディに
なったので記録しておく。

## Run 1: 素朴なミラー適応度(margin 3pt、アンカーなし)

- 昇格 6 回。しかし最終チャンピオンは**デフォルト重みに 47.2%**(600 戦)
- 300 戦の適応度は σ≈2.9pt。3pt マージンは約 1σ で、60 回試せば
  偽陽性が数回混ざり、それが**単調に蓄積して劣化**する

## Run 2: アンカー付き(margin 5pt + 昇格時にデフォルトとも対戦)

- 昇格 2 回、最終チャンピオンは**ミラーでデフォルトに 52.8%**(600 戦)
- ところがベースライン転移で崩壊: **vs first 68% → 58%**
- ミラー適応度は「自分(と同型)に勝つ」ことだけに最適化され、
  異質な相手への汎化を犠牲にする — 対戦型学習の過学習そのもの

## Run 3: 混合適応度(ミラー + vs first、両軸無退行ゲート)

- 適応度 = ミラー勝率 + vs first 勝率、昇格には両者合計で +5pt 必要
- **50 イテレーションで昇格 0** — この予算では、手調整デフォルトを
  汎化込みで有意に上回る重みは見つからなかった
- 最終ゲートが正しく作動し、weights_best.json は書かれずデフォルト維持
  (ログ: selfplay_run.json)

## 結論と示唆

1. **手調整デフォルトは重み空間の中で相当ロバスト**。デッキ探索
   (claude/ptcg-deck-search) の「デフォルトデッキは局所最適」と同じ構図
2. 伸びしろは定数チューニングではなく**構造の変更**にある。実際、
   claude/ptcg-search-agent のエネルギールーティング(構造変更)は
   +5pt を出した
3. 本気で学習するなら: 評価回数を racing(逐次棄却)で節約、CMA-ES など
   集団ベース、相手プールの多様化(過去チャンピオン+ランダム+first)、
   そして最終的には方策そのものの学習(NN)へ

## 使い方

```bash
python train_selfplay.py --games 300 --iters 50 --margin 0.05 --seed 2
# 改善が見つかった場合のみ weights_best.json が書かれ、
# agent.py が import 時に自動ロードする
```
